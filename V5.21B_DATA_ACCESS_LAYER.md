## 2. Architecture retenue (V5.21B)

Choix de structure a risque minimal:
- Implementation dans [app.js](app.js) (pas de nouveaux scripts a charger, pas de risque d'ordre de chargement GitHub Pages/file://).

Ajout:
- `BrowserStorageAdapter` dans [app.js](app.js#L128)

Responsabilites:
- `getRaw`, `setRaw`, `remove`, `has`, `keys`, `get`, `set`
- gestion d'erreurs structurees (quota, lecture/ecriture, JSON invalide)

## 14. Risques residuels

1. JSON corrompu preexistant en stockage local:
- peut toujours provoquer une erreur de lecture (design volontaire, pas d'effacement automatique)

2. Quota navigateur:
- erreur maintenant structuree, mais la capacite locale reste limitee

3. Couverture tests metier:
- necessite execution manuelle complete du protocole non-regression pour clore V5.21B

4. Performance imports volumineux:
- logique metier inchangee, mais le quota localStorage reste un risque structurel

## 15. Plan propose pour V5.21C

1. Ajouter un `RemoteStorageAdapter` (sans activer en prod)
2. Ajouter un `HybridStorageAdapter` sous feature flag
3. Introduire un namespace futur `workspaceId/userId` dans la couche repository (sans casser cles legacy)
4. Mettre en place tests de parite automatique local vs hybride
5. Conserver rollback vers local-only tant que la parite n'est pas strictement validee
