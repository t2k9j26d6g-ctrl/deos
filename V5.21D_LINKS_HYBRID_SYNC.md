# DEOS V5.21D - Synchronisation hybride pilote des Liens

Date: 2026-08-05
Base: DEOS V5.20.5 + V5.21B + V5.21C

## 1. Diagnostic réel avant modification

### Structure réellement utilisée pour `state.links`

La collection locale est un tableau simple chargé depuis `deos_links`, normalisé par `normalizeEntity("links", item)`.

Structure constatée dans `app.js`:

- `id`: identifiant local stable, conservé tel quel.
- `name`: nom du lien.
- `url`: URL normalisée via `linkUrl(...)`.
- `category`: catégorie, défaut `Autre`.
- `description`: description libre.
- `status`: `actif`, `à vérifier`, `archivé`.
- `favorite`: booléen.
- `icon`: emoji/icône.
- `order`: nombre utilisé pour le tri manuel.
- `createdAt`
- `updatedAt`
- autres champs éventuels conservés si présents dans l'objet local.

### Clé locale réellement utilisée

- `deos_links`

### Repository actuel

- `entityRepositories.links`
- construit par `createRepository(deosDataService, { key: "links", fallbackFactory: () => [], normalize: value => normalizeCollection("links", value) })`

### Normalisation actuelle

- `normalizeEntity("links", item)`
- valeurs par défaut:
  - `name: ""`
  - `url: ""`
  - `category: "Autre"`
  - `description: ""`
  - `status: "actif"`
  - `favorite: false`
  - `icon: ""`
  - `order: Date.now()`
  - `createdAt: isoToday()`
  - `updatedAt: isoToday()`
- post-traitements:
  - `favorite` forcé en booléen
  - `icon` suggéré automatiquement si vide
  - `order` forcé en nombre

### Fonctions métier réellement utilisées

- création: `addLink()`
- modification: `saveLink(id)`
- suppression: `deleteLink(id)`
- archivage/réactivation: `archiveLink(id)`
- favori: `toggleLinkFavorite(id)`
- ordre: `moveLink(id, delta)`
- ouverture externe: `openExternalLink(id)`
- mise en avant Cockpit: `cockpitFavoriteLinks()`

### Champs legacy ou variantes constatés

- aucune variante legacy spécifique aux Liens n'a été trouvée dans `normalizeEntity("links", ...)`.
- le code métier travaille sur `name` et non `title`.

### Liens visibles sur le Cockpit

- seuls les favoris non archivés sont visibles dans le bandeau `cockpitFavoriteLinks()`.

### Écritures déclenchées au rechargement

`init()` relit puis réécrit chaque collection, y compris `links`:

1. `state.links = saved("links", await loadJson("links"))`
2. `persist("links")`

Conclusion: le bootstrap réécrit `deos_links` après normalisation à chaque démarrage. Les métadonnées de synchronisation ne doivent donc pas polluer l'objet métier affiché ni le repository local des Liens.

## 2. Schéma SQL retenu

Migration créée:

- `supabase/migrations/002_v5_21d_links_hybrid.sql`

Table créée:

- `public.deos_links`

Colonnes:

- `id uuid primary key default gen_random_uuid()`
- `workspace_id uuid not null`
- `owner_id uuid not null`
- `client_id text not null`
- `data jsonb not null`
- `created_at timestamptz`
- `updated_at timestamptz`
- `deleted_at timestamptz null`
- `version integer not null default 1`

Contraintes:

- `unique(workspace_id, client_id)`
- `data` doit rester un objet JSON simple
- garde SQL contre les payloads qui ressemblent à un état global DEOS

Index:

- `workspace_id`
- `client_id`
- `updated_at`
- `deleted_at`
- index actif sur `workspace_id` + `updated_at` avec `deleted_at is null`

## 3. Politiques RLS

Fonctions réutilisées ou ajoutées:

- `deos_is_workspace_member(...)`
- `deos_can_write_workspace(...)`
- `deos_workspace_role(...)`
- `deos_current_workspace_id()`
- `deos_link_payload_is_safe(...)`

RLS sur `deos_links`:

- aucun accès anon
- lecture uniquement pour le membre du workspace actif
- création uniquement si `owner_id = auth.uid()` et rôle `owner/admin/contributor`
- mise à jour uniquement si rôle `owner/admin/contributor`
- pas de `DELETE` physique exposé
- `workspace_id` forcé au workspace actif côté RLS

Protection visée:

- une modification manuelle de `workspace_id` dans le navigateur ne permet pas de viser un autre workspace, même si l'utilisateur est authentifié.

## 4. Adapter distant Liens

Fichier modifié:

- `remote-adapter.js`

API ajoutée, strictement limitée aux Liens:

- `listLinks()`
- `getLink(clientId)`
- `createLink(link)`
- `updateLink(clientId, patch, expectedVersion)`
- `softDeleteLink(clientId, expectedVersion)`

Garde explicite:

- aucun endpoint générique métier n'a été ajouté
- le payload d'un Lien est refusé s'il contient des clés évoquant `actions`, `documents`, `managers`, `state`, `settings`, etc.

Comportement distant:

- `client_id` reste l'id local stable DEOS
- `data` transporte uniquement le métier du Lien
- les tombstones `deleted_at` sont lus pour propager les suppressions entre navigateurs

## 5. Repository hybride Liens

Fichier modifié:

- `app.js`

Objet dédié:

- `linksHybridRepository`

Méthodes principales:

- `loadRuntime()`
- `analyze()`
- `activate()`
- `deactivate()`
- `syncNow()`
- `queueUpsert(link, operation)`
- `queueDelete(clientId, snapshot)`

Règle de fonctionnement V5.21D:

- `localStorage` reste le support immédiat de l'interface
- Supabase ne sert que de miroir distant des Liens quand le pilote est activé
- aucune bascule globale de source de vérité
- aucun autre repository métier n'est redirigé vers Supabase

États gérés:

- `LOCAL_ONLY`
- `SYNC_READY`
- `SYNCING`
- `SYNCED`
- `OFFLINE`
- `CONFLICT`
- `ERROR`

## 6. File d'attente technique

Clés techniques ajoutées:

- `deos_sync_meta_links`
- `deos_sync_queue_links`

Contenu de `deos_sync_queue_links`:

- `operation`
- `clientId`
- `queuedAt`
- `expectedVersion`
- `payload`
- `attempts`
- `lastError`

Règles:

- pas de token
- pas de session
- pas de mot de passe
- pas d'autre objet métier
- fusion des opérations successives par `clientId` quand c'est sûr
- `delete` remplace un `upsert` en attente pour le même Lien

## 9. Gestion des conflits

Chaque conflit expose:

- le Lien concerné
- la version locale technique (`localRevision`)
- la version distante (`remoteVersion`)
- la date locale
- la date distante
- les champs différents

Choix disponibles:

- conserver la version locale
- conserver la version distante
- fusionner manuellement
- reporter la décision

La fusion manuelle couvre explicitement les champs simples:

- nom
- URL
- description
- catégorie
- favori
- statut
- ordre
- icône

Règle importante:

- aucun `last write wins` silencieux n'est appliqué à un conflit réel.

## 10. Hors ligne

Comportement prévu:

- création locale possible hors ligne
- modification locale possible hors ligne
- favori local possible hors ligne
- archivage local possible hors ligne
- suppression locale possible hors ligne
- mise en file technique si le backend n'est pas joignable

Limite:

- la reprise automatique a été câblée côté frontend, mais la validation multi-appareils réelle reste à exécuter sur backend vivant.

## 11. Retour arrière

Bouton Paramètres ajouté:

- `Désactiver la synchronisation`

Effet:

- arrête les appels distants Liens futurs
- conserve les Liens locaux
- ne supprime aucune donnée distante
- conserve la file technique locale
- remet l'état pilote à `Désactivée`

Suppression distante volontaire:

- non implémentée dans cette version
